# FootballManager — שלב 8, הלקוח השני וספר הפרויקט

הפתרון כולל את לקוח WPF הראשון, אתר הלקוח השני, שירות CoreWCF ופרויקט FootballManager.Contracts המשותף. מסד ההדגמה נמצא ב־FootballManager.WCF/Data/FootballManager.accdb וכולל את הטבלאות ונתוני הדמה של C1–C4. באתר נכנסים בדף הבית ופותחים את אזור התוכן בכתובת /content.html כדי לנהל שחקנים, קבוצות, משחקים, העברות וסטטיסטיקות לפי התפקיד. השרת אוכף הרשאות על אותן פעולות בשני הלקוחות.

## הפעלה מקומית ב־Windows

נדרשים .NET 9 SDK ו־Microsoft ACE OLE DB 16.0 בגרסת 64 סיביות. מחלצים את קוד המקור לתיקייה מקומית שיש בה הרשאת כתיבה. מתיקיית הפתרון מפעילים ב־PowerShell:

```powershell
dotnet build .\FootballManager.WPF.sln
.\Start-Server.ps1
```

משאירים את השירות פועל. מחלון PowerShell שני, באותה תיקייה, מפעילים את הלקוח:

```powershell
dotnet run --project .\FootballManager.WPF\FootballManager.WPF.csproj
```

כתובת השירות היא http://localhost:5152/FootballManagerService והאתר של C2 זמין ב־http://localhost:5152/. רק השרת פותח את קובץ Access.

## התנסות ביכולות הקיימות ובסקאוט AI

1. נכנסים ל־WPF עם DemoManager ופותחים **העברות וסטטיסטיקות** בדשבורד. בשתי הכרטיסיות יש רשימה, טופס ופקודות לשליפה, הוספה, עדכון ומחיקה דרך WCF. לאחר שמירה הרשימה נטענת מחדש מהשירות.
2. אחרי שמירת העברה, נכנסים עם DemoPlayer. כפתור **בדיקת הרשאה להעברה** שולח אותה בקשת שמירה דרך WCF ומציג `403 Forbidden`. נתוני ההעברה אינם משתנים. Admin ממשיך לנהל משתמשים ואינו מורשה ל־C4.
3. עם DemoPlayer פותחים **סקאוט AI**, בוחרים שחקן ולוחצים **נתח שחקן**. השירות בודק את ה־Session והתפקיד בשרת, שולף את הפרופיל הציבורי מ־Access, שולח לספק AI מהשרת בלבד ומציג את התשובה. אין חיבור למסד מהמסך ואין שמירת ניתוח במסד.
4. עם DemoManager או Admin פותחים את אותו מסך ולוחצים על אותה פעולת ניתוח: WCF מחזיר `403 Forbidden`. ללא Session השירות מחזיר `401 Unauthorized`. גם כשאין מפתח, רשת או תשובת AI, המסך מציג הודעה ונשאר פתוח.
5. במסכי WPF הקיימים אפשר לבדוק את הכניסה של C1, יכולות C2 ו־C3 ואת ה־CRUD של C4.

## הגדרת שירות AI בשרת

גם ניתוח הסקאוט וגם הצ׳אט משתמשים כעת ב־Gemini דרך השרת. יש להגדיר את `FOOTBALLMANAGER_GEMINI_API_KEY` במשתני הסביבה של המשתמש במחשב שמריץ את WCF, ואז להפעיל את `Start-Server.ps1`. המפתח אינו נמצא בקוד, ב־WPF, במסד או באתר.

## צ׳אט Gemini ב־WPF

בחלון צ׳אט בינה משתמש Player שולח שאלה דרך WCF. השרת מזהה את המשתמש, טוען שחקנים ומועדפים מ־Access, מחזיק היסטוריית שיחה נפרדת לכל משתמש בזיכרון ופונה ל־Gemini. הוספה למועדפים מתבצעת רק כאשר הוזכר שם מלא של שחקן יחיד והמודל החזיר את מזהה אותו שחקן. אורח מקבל 401 ותפקיד אחר מקבל 403. הלקוח השני אינו קורא לשירות הבינה.

להפעלה יוצרים מפתח API בחשבון Google AI Studio של בעל הפרויקט ומגדירים בשרת FOOTBALLMANAGER_GEMINI_API_KEY. מפעילים מחדש את השרת. ברירת המחדל היא gemini-3.1-flash-lite ואפשר לשנות באמצעות Gemini:Model בהגדרות השרת. ללא מפתח אמיתי מתקבלת 503. אין לשמור את המפתח בקוד, במסד או בקובץ ההגשה.
## סיסמאות להדגמה מקומית

המסד מכיל גיבובי סיסמאות ב־Users.PasswordHash. הסיסמאות נמסרו בנפרד בחבילת C2. כדי לקבל סיסמאות הדגמה חדשות, עוצרים את השירות ומריצים על עותק עבודה מקומי את הפקודה הבאה. היא מקצה סיסמאות לשלושת חשבונות ההדגמה ומציגה אותן פעם אחת. לאחר מכן מפעילים שוב את השירות.

```powershell
dotnet run --project .\FootballManager.WCF\FootballManager.WCF.csproj -- --prepare-demo-accounts
```
